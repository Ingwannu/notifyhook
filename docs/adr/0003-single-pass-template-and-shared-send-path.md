# ADR 0003: 템플릿 한 번 치환과 테스트·실제 전송 경로 통합

- 상태: 채택 (1.0.36)
- 관련 코드: `data/TemplateEngine.kt`, `ui/HookEditActivity.kt`, `service/HookDeliverySender.kt`

## 배경

- `TemplateEngine`은 변수마다 `String.replace`를 순서대로 반복했다. 앞에서 치환한 값 안에 `{text}`나 `{global.이름}` 같은 문자열이 있으면 다음 단계에서 다시 치환되었다.
  예: 알림 제목이 `literal {text} and {global.secret}`이면 서버에는 `literal body and s3cr3t`가 갔다(기존 코드에서 테스트로 재현함).
  알림 내용에 따라 전역 변수 값이 본문에 섞여 들어가는 경로이기도 했다.
- JSON 이스케이프가 `\ " \n \r \t`만 처리해, 알림에 다른 제어 문자(U+0000..U+001F)가 섞이면 깨진 JSON이 전송되었다.
- 편집 화면의 "테스트"는 치환과 HTTP 요청을 별도 코드로 구현했다. 그 결과
  - 정규식 로컬 변수를 실제 엔진은 `{var_이름}`으로, 테스트는 `{이름}`으로 치환했다(도움말은 `{var_이름}`). 도움말대로 쓰면 테스트 결과에 변수가 치환되지 않은 채 나왔다.
  - 테스트만 `{{변수}}`도 치환했다.
  - 헤더 기능(ADR 0001)을 두 곳에 똑같이 구현해야 했다.

## 검토한 대안

1. 기존 반복 replace 유지 + 테스트 코드만 맞추기: 이중 치환 문제가 남는다.
2. 치환값 안의 중괄호를 이스케이프: 서버가 받는 값 자체가 바뀐다.
3. 템플릿을 한 번만 훑으며 `{이름}`을 값 표에서 찾아 바꾸고, 테스트는 실제 엔진·전송기를 그대로 호출: 치환 결과를 다시 훑지 않아 값이 보존되고, 테스트 결과가 실제 전송과 같다.

## 결정

- `TemplateEngine.processFields`는 정규식 `\{([^{}]+)\}`로 한 번만 훑는다. 표에 없는 `{이름}`과 JSON 중괄호는 그대로 둔다.
  변수 이름 공간: 기본 변수(`title` 등), `var_<이름>`(정규식 로컬), `global.<이름>`(전역).
- JSON 이스케이프는 U+0000..U+001F 제어 문자를 모두 처리한다(`\b`, `\f`, 그 외 `\u00XX`).
- 테스트 전송은 샘플 알림 값으로 `TemplateEngine.processFields`를 호출하고(전역 변수는 저장하지 않음),
  `HookDeliverySender.newCall/execute`로 실제와 같은 요청을 보낸다.

## 결과

- 알림 내용과 관계없이 템플릿 결과가 예측 가능하다. 테스트가 성공하면 실제 전송도 같은 요청이다.
- 이전에 테스트에서만 동작하던 `{이름}`(var_ 없이)과 `{{변수}}` 표기는 테스트에서도 더 이상 치환되지 않는다. 실제 전송에서는 원래부터 치환되지 않았으므로 실제 동작은 바뀌지 않는다.
